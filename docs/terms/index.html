Purpose and who it covers

The connector is intended only for the owner, to connect an Oura account the owner has a right to access, and to view, summarize, and analyze that information through Grok Bot / HealthBot. It is not offered to other people, and it does not provide a public connection service. The connector is intended to run with tokens stored on the owner's own server.

These terms describe this connector's boundaries. They do not speak for Oura or for Grok Bot, they do not modify those parties' separate agreements, and they are not a compliance warranty.

Read limits

The connector is described as reading with GET routes. It is not a way to write health data. The evidence recorded for this version is that implementation revision fixed65ceeb07 has 35 implemented GET routes, 113 mock tests, and a credential-free handshake covering 36 tools. Those are limited tested metadata. They do not prove a production deployment or a live scope. Whether those 35 routes match every public production route is unverified. They are not all of the data a person can see in the consumer app, and this page does not promise that every route works on this account. Webhook management and sandbox use are outside the health-read description on this page.

No live grant has been made. A planning list named eight scopes: email, personal, daily, heartrate, workout, tag, session, and spo2. A developer interface reportedly lists 11 scopes, including Ring Configuration, Stress, and Heart Health. Exact live grants and routes are unverified. Neither list establishes that every data category is authorized or available.

What comes back depends on the grant, the device, the subscription, whether the data exist, and the API and network conditions. A missing result, an empty result, or an error does not by itself mean that a health event did not happen, and it is not a medical judgment. The connector is not a medical device.

Not for medical use

Summaries, trends, explanations, or suggestions from the connector or from Grok Bot / HealthBot are personal information for the owner to consider. They are not a diagnosis, a treatment plan, a prescription, or emergency care, and they do not replace a qualified clinician.

Do not start, stop, or change a treatment based only on these results. For symptoms, an abnormal result, or a health question, consult a qualified clinician. In an emergency, contact local emergency services rather than waiting for the connector or for a chat reply.

Credentials, security, and privacy

The owner should turn the connector on only after understanding and accepting the data path and the storage risks. That decision has not been carried out. OAuth has not been performed. Tokens are intended to be stored on the owner's server, but health data that is read still passes through Grok Bot's cloud service and may enter chat. The connector is not an arrangement that stays entirely on the owner's machine. These pages do not promise zero retention, and they do not promise that health information stays only with the owner.

Server permissions, a key ring on the same machine, administrator access, and backups can all affect whether authorization material stays confidential. SSH is not encryption at rest, and file modes are not absolute isolation. The privacy page states the known boundary. Security isolation is being implemented separately. Security isolation is pending and has not been verified. Encryption at rest is not assured. Root access or the same user id remains a risk. No backup cycle or retention period is promised.

Do not send a token, an authorization code, or a private key to ordinary chat or to a public page. If authorization material may have leaked, stop the calls, revoke the authorization in the function Oura provides, and have an operator review the server and the related access. Deleting a local cache is not enough.

Stopping and recovery

The owner can stop the calls. An operator can run local logout or another cleanup. Local logout deletes the connector's local token and clears the connector's cache. It does not revoke authorization at Oura, and it does not delete Oura source records, existing chat, system records, or backups. Local logout is not remote revocation and is not platform deletion.

If a token refresh has an unknown result, or the new token is not saved locally, a new sign-in may be required. Automatic recovery is not assured, and exactly-once recovery is not assured. A refresh whose result is unknown should not be retried blindly. An explicit recovery should wait until the risk has been confirmed.
