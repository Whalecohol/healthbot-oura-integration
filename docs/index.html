HealthBot Personal Oura Integration

Not enabled. Provisional draft, dated 8 November 2026 (2026-11-08). The owner has not adopted this text.

The date is a drafting date. It is the record of when this explanation was written, before activation.

This page describes a planned personal experiment: a single-user connection between the owner's Oura account and the owner's AI assistant, HealthBot. The intended path uses Oura's official OAuth and a community open-source MCP server. The integration is not enabled.

How to read this page

The text is provisional. It was drafted on 8 November 2026 (2026-11-08). The owner has not adopted this text as a privacy policy, as terms of service, or as a description of a running service. Publishing the draft leaves the integration disabled.

Several facts that a running integration would need are still open. Exact OAuth scopes, the data and model providers, any other recipients, token and data storage, retention and deletion, and an operator contact are unconfirmed.

These pages do not submit an Oura application, do not grant health-data authorization, and do not accept Oura's API agreement.

Intended purpose

The integration is intended for one person, the owner, for personal and non-commercial use. It is a single-user experiment. The intended purpose is to let the owner ask HealthBot about the owner's own Oura information.

HealthBot Personal Oura Integration is not affiliated with or endorsed by Oura Health Oy. It is a separate personal project.

The intended integration is not a medical device and would not give medical advice. This draft claims no medical, security, or compliance certification.

Intended setup

The planned host is a shared hosted computer used by the owner's AI assistants. That computer is separate from the owner's physical machine. The intended design would place tokens and retrieved Oura information on that shared host.

The software intended to run there is the community open-source .NET MCP server gjlumsden/oura-mcp. MCP means Model Context Protocol, a way for an assistant to call tools on a server. This repository publishes these explanatory pages only. It does not include that server, OAuth code, API credentials, or a connection to Oura.

The intended connection is the owner's own Oura account through Oura's official OAuth. The design uses that official OAuth path directly, with no other health platform added between the owner and Oura.

Intended data path

The steps below describe the design the owner would still have to turn on. They do not describe activity this website performs.

  1. The owner approves access on Oura's site through Oura's official OAuth.
  2. The MCP server on the shared hosted computer receives access tokens and requests the owner's Oura data in the scopes the owner approved. The exact scopes are unconfirmed.
  3. HealthBot calls the server's tools. Oura information returned to HealthBot becomes part of the assistant's conversation. That information may be sent through HealthBot to the AI service providers that process the conversation. Which providers those are is unconfirmed.

What remains unconfirmed

Exact OAuth scopes
Unconfirmed. This draft does not name the scopes that would be requested. Categories Oura can offer, such as sleep, activity, readiness, or heart rate, are examples of available data types, and they are not a chosen scope list.
Data and model providers
Unconfirmed. The names of the AI service providers, and the terms that would apply to information sent to them, are not settled here.
Other recipients
Unconfirmed. The intended path already includes a possible send through HealthBot to its AI service providers. Any recipient beyond that path is unconfirmed.
Token and data storage
Unconfirmed. Whether the server would store tokens or Oura data on the hosted computer, and where, is unconfirmed.
Retention and deletion
Unconfirmed. How long tokens, Oura data, or conversation logs would be kept, and how deletion would work, is unconfirmed.
Operator contact
Unconfirmed. No contact method is stated, because none has been confirmed.

This draft sets no rule against sharing, selling, or advertising, and it describes no control that would prevent them.
